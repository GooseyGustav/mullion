# License service

One Go binary that issues, signs, and validates licenses for **Mullion**, **Fat Cat
Pomodoro**, and any later product. It also receives Stripe webhooks, sends license
email, and serves a small admin dashboard.

The interface contract is [`../docs/COORDINATION.md`](../docs/COORDINATION.md). This
file covers only the server implementation.

## Status

Foundation only. Implemented and tested:

- `internal/license/key.go` — key format, normalization, SHA-256, AES-GCM at rest
- `internal/license/signer.go` — Ed25519 key generation, PEM load/save, `LIC1`
  envelope signing and verification
- `internal/license/*_test.go` — round trip, tampering, wrong key, wrong secret

Next: `internal/config`, `internal/store` (SQLite schema, seats, orders,
subscriptions, webhook events), `internal/stripe` (Payment Links metadata, webhook
signature), `internal/mail` (Resend + log fallback), `internal/web` (public API,
webhook, admin), `cmd/license-server/main.go`.

## Key format

```
PREFIX-XXXXX-XXXXX-XXXXX-XXXXX
```

- Alphabet `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (no `0`, `O`, `1`, `I`).
- 20 random characters = 100 bits.
- Prefixes: `MULL`, `FATC`.
- The database stores `sha256(normalize(key))` and an AES-GCM ciphertext for
  resend/recovery. Plaintext keys are never logged.

## Signed envelope

```
LIC1.<payload_b64url>.<signature_b64url>
```

Ed25519 over the exact base64url payload bytes. Payload v1:

```json
{
  "v": 1,
  "kid": "2026-11",
  "license_id": "lic_...",
  "product": "mullion",
  "plan": "pro",
  "status": "active",
  "seats": 3,
  "major": 1,
  "issued_at": "2026-11-13T12:00:00Z",
  "expires_at": null,
  "install_id": "<random 64 hex>",
  "key_hint": "MNPQR"
}
```

- `major` is the highest app major the license can run. `1` means free 1.x, paid 2.0.
- `expires_at` is `null` for one-time licenses and period end + 3 days for
  subscriptions.
- `install_id` is a random value generated by the app and stored in Keychain. No
  hardware identifier leaves the Mac.
- Apps ignore unknown fields, so claims are additive.

## Planned endpoints

```
POST /v1/activate     {license_key, install_id, app_version, os_version, device_name?}
POST /v1/refresh      {license_key, install_id}
POST /v1/deactivate   {license_key, install_id}
POST /v1/recover      {email}                    alias: /v1/resend
GET  /v1/public-key
POST /webhooks/stripe                            alias: /v1/webhook/stripe
GET  /portal?t=...
GET  /healthz
GET  /admin*
```

Errors are `{ "error": "code", "message": "human" }` with status 400, 404, 409,
410, 429, or 500. `/v1/recover` always returns 202, whether or not the address
exists.

## Configuration

Environment variables, loaded once at startup. Secrets live in
`/etc/mullion/license.env` (mode 600), never in git.

| Variable | Purpose |
|---|---|
| `ADDR` | listen address, default `127.0.0.1:8080` |
| `DB_PATH` | SQLite file, e.g. `/var/lib/mullion/licenses.db` |
| `PUBLIC_BASE_URL` | `https://api.asifthatworks.com` |
| `SITE_BASE_URL` | `https://asifthatworks.com` |
| `SIGNING_KEY_PATH` | PKCS#8 PEM Ed25519 private key |
| `SIGNING_KEY_ID` | `kid`, e.g. `2026-11` |
| `KEY_ENCRYPTION_SECRET` | AES-GCM secret for key recovery |
| `SESSION_SECRET` | admin cookie/CSRF signing |
| `ADMIN_USER`, `ADMIN_PASSWORD` | dashboard basic auth |
| `ADMIN_ALLOW_CIDR` | optional IP allowlist |
| `STRIPE_SECRET_KEY` | server-side Stripe API |
| `STRIPE_WEBHOOK_SECRET` | `whsec_...` for signature verification |
| `RESEND_API_KEY` | transactional email |
| `MAIL_FROM`, `MAIL_REPLY_TO` | sender identity |
| `DEV_MODE` | local only: log email instead of sending |

Generate a signing key once, back it up offline, and never rotate it without
keeping the old public key in shipped apps:

```bash
go run ./cmd/genkey -kid 2026-11 -out /etc/mullion/signing-key.pem
```

## Build, test, run

```bash
cd server
go test ./...
go vet ./...
go build ./cmd/license-server
```

SQLite uses `modernc.org/sqlite` so the binary is pure Go and deploys as a single
file. WAL mode, foreign keys, and a busy timeout are set on open.

## Security notes

- Bind to `127.0.0.1`; Caddy/nginx terminates TLS.
- Verify `Stripe-Signature` with a 5-minute tolerance; use the event id for
  idempotency and return 500 on transient failures so Stripe retries.
- Rate-limit activation, refresh, recover, and portal by IP and by key hash.
- Never log full keys, emails, or install ids. Log license ids and key hints.
- Back up SQLite nightly; test a restore before launch.
